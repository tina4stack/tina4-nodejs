# Queue

Tina4 includes a file-backed job queue for background processing. No Redis, no RabbitMQ -- just the file system. Zero dependencies.

## Basic Usage

```typescript
import { Queue } from "@tina4/core";

const queue = new Queue();

// Push a job onto a named queue
const jobId = queue.push("emails", {
  to: "alice@example.com",
  subject: "Welcome!",
  body: "Thanks for signing up.",
});
console.log("Job ID:", jobId);

// Pop the next pending job
const job = queue.pop("emails");
if (job) {
  console.log("Processing:", job.payload);
  // Process the job...
}
```

## Job Lifecycle

Jobs move through these states:

1. **pending** -- Waiting in the queue
2. **reserved** -- Popped by a worker (temporarily held)
3. **failed** -- Moved to the failed directory after errors

## Queue Operations

```typescript
const queue = new Queue();

// Push with delay (seconds)
queue.push("notifications", { message: "Hello" }, 30); // Available after 30 seconds

// Pop returns null if no pending jobs
const job = queue.pop("notifications");

// Get queue size
const size = queue.size("emails");  // Number of pending jobs

// List all jobs in a queue
const jobs = queue.list("emails");

// Peek at the next job without removing it
const next = queue.peek("emails");

// Mark a job as failed
queue.fail("emails", jobId, "Connection timeout");

// Retry failed jobs
queue.retry("emails");

// Purge all jobs from a queue
queue.purge("emails");
```

## Worker Pattern

Process jobs continuously:

```typescript
import { Queue } from "@tina4/core";

const queue = new Queue();

async function worker(): Promise<void> {
  while (true) {
    const job = queue.pop("emails");

    if (job) {
      try {
        await sendEmail(job.payload as EmailPayload);
        console.log(`Processed job ${job.id}`);
      } catch (err) {
        queue.fail("emails", job.id, String(err));
        console.error(`Job ${job.id} failed:`, err);
      }
    } else {
      // No jobs available, wait before polling again
      await new Promise((r) => setTimeout(r, 1000));
    }
  }
}
```

## QueueJob Interface

```typescript
interface QueueJob {
  id: string;                     // UUID
  payload: unknown;               // Your job data
  status: "pending" | "reserved" | "failed";
  createdAt: string;              // ISO timestamp
  attempts: number;               // Number of processing attempts
  delayUntil: string | null;      // ISO timestamp for delayed jobs
  error?: string;                 // Error message (failed jobs only)
}
```

## Configuration

```typescript
const queue = new Queue("file", {
  backend: "file",             // Currently only "file" supported
  path: "data/queue",          // Storage directory (default: "data/queue")
});
```

### Environment Variables

```bash
# .env
TINA4_QUEUE_BACKEND=file
TINA4_QUEUE_PATH=data/queue
```

## Storage Structure

```
data/queue/
  emails/
    abc123.json         # Pending job
    def456.json         # Pending job
    failed/
      ghi789.json       # Failed job
  notifications/
    jkl012.json
```

## Notes

- Jobs are stored as individual JSON files for simplicity and crash safety.
- The file-based queue is suitable for moderate throughput. For high-volume workloads, consider an external queue system.
- Job IDs are UUIDs generated by `crypto.randomUUID()`.
- Delayed jobs include a `delayUntil` timestamp and are skipped until that time.
